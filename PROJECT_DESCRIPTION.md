# Проект: Прошивка ESP32 «Vyroslo-board» — Умная Теплица v2.0

## 🌱 Назначение

Полнофункциональная прошивка для ESP32, реализующая IoT-контроллер умной теплицы в соответствии с **ESP32 Integration Guide v2**. Устройство представляет собой тонкий клиент с богатой локальной функциональностью, включающей OLED дисплей с энкодером, многоканальные датчики через мультиплексор, управление 8-канальными реле и полную интеграцию с платформой Vyroslo.

**Базовый URL сервера:** `https://vyroslo.replit.app`
**Идентификатор устройства:** `gh-02`
**Архитектура:** Монолитная (все функции в main.cpp)

---

## 🔧 Аппаратная конфигурация

### **Основные компоненты:**
- **MCU:** ESP32-WROOM-32 (240MHz, 320KB RAM, 4MB Flash)
- **Дисплей:** SSD1306 OLED 128x64 (I2C: SDA=22, SCL=23)
- **Датчики:** SHT31 (температура/влажность) на I2C: SDA=16, SCL=17
- **Интерфейс:** Rotary Encoder (CLK=15, DT=2, SW=4)
- **Реле:** 8-канальный модуль (ACTIVE LOW) на пинах {13,14,27,26,25,33,32,35}
- **Мультиплексор:** CD74HC4067 (16 каналов почвенных датчиков)
- **Индикация:** Опциональные LED для статуса

### **Распиновка мультиплексора:**
```
SIG = 34 (ADC1_CH6 - только вход)
S0  = 21, S1 = 19, S2 = 18, S3 = 5
EN  = GND (постоянно активен)
CH15 = GND (калибровочный канал)
CH14 = датчик уровня воды
CH0-CH13 = датчики влажности почвы
```

### **I2C конфигурация:**
```cpp
// Раздельные I2C шины (как требовал пользователь)
Wire0 (SHT31):  SDA=16, SCL=17
Wire1 (OLED):   SDA=22, SCL=23
```

## 🌐 Серверная интеграция

### **1. Аутентификация (POST /api/v1/device/auth)**

**Запрос каждые 7 дней или при 401:**
```json
{
  "device_id": "gh-02",
  "secret": "daad861d-e1df-4fb3-9668-c4382e437f71",
  "fw": "v1.1.0",
  "hw": "ESP32-Wroom-32"
}
```

**Ответ 200 OK:**
```json
{
  "success": true,
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expires_in": 604800,
  "device": {
    "id": "gh-02",
    "name": "gh-02",
    "type": "greenhouse"
  },
  "polling": {
    "telemetry_sec": 60,
    "config_sec": 300
  }
}
```

**Автоматическое применение интервалов:**
- `polling.telemetry_sec` → обновляет TELEMETRY_SEC (по умолчанию 10, сервер: 60)
- `polling.config_sec` → обновляет CONFIG_SEC (по умолчанию 60, сервер: 300)

**Обработка ошибок:**
- **401** → authBlocked = true, блокировка до перезагрузки
- **429** → экспоненциальный backoff с Retry-After
- **5xx** → повторная попытка через delay

### **2. Телеметрия (POST /api/v1/device/telemetry)**

**Интервал:** каждые 10 секунд
**Формат (соответствует Integration Guide v2):**
```json
{
  "device_id": "gh-02",
  "ts_ms": 1736723456000,
  "air": [
    {
      "id": "air_top",
      "t_c": 19.5,
      "rh": 62.3
    },
    {
      "id": "air_bot",
      "t_c": 18.9,
      "rh": 65.1
    }
  ],
  "soil": [
    {
      "id": "soil_01",
      "percentage": 45.2,
      "raw": 2048
    }
  ],
  "relays": [
    {
      "id": "light_top",
      "state": true,
      "duration_ms": 30000
    }
  ],
  "water": {
    "low": false
  }
}
```

### **3. Система манифестов (NEW!)**

**Умная синхронизация манифестов:**
Устройство реализует интеллектуальную систему управления манифестами:

1. **GET /api/v1/device/manifest** с `If-None-Match: <etag>`
   - Проверка существования и актуальности манифеста
   - **200** - манифест изменился, обновляем ETag
   - **304** - манифест актуален, ничего не делаем
   - **404** - манифест не найден, требуется загрузка

2. **PUT /api/v1/device/manifest** (только при необходимости)
   - Загрузка только когда манифест отсутствует или изменился
   - Автогенерация полного описания устройства:
     * I2C конфигурация (SHT31 на 0x44, 0x45)
     * 16 аналоговых датчиков почвы через мультиплексор
     * 8 реле с GPIO назначениями и типами
     * OLED дисплей и rotary encoder
     * Калибровочные данные и пороги

**Частота проверки:** при аутентификации + каждый час
**ETag кеширование:** персистентное хранение в NVS
**Предотвращение спама:** загрузка только при отсутствии (404)

### **4. Heartbeat (HEAD /api/)**

**Простой heartbeat (рекомендуемый):**
- **Интервал:** каждые 5 секунд
- **Метод:** HEAD /api/ (минимальный трафик)
- **Авторизация:** не требуется
- **Назначение:** поддержание online статуса

### **5. Конфигурация (GET /api/v1/device/config)**

**Интервал:** каждые 60 секунд
**ETag кеширование:** If-None-Match заголовок
**Применение:** автоматическое обновление интервалов опроса

### **6. WebSocket управление (wss://vyroslo.replit.app/ws?token=JWT)**

**Новый батч-формат команд:**
```json
{
  "type": "relay_control",
  "cmd_id": "cmd_12345",
  "actions": [
    {
      "relay": "humidifier",
      "state": true,
      "timeout_sec": 30
    }
  ]
}
```

**ACK ответы:**
```json
{
  "type": "ack",
  "cmd_id": "cmd_12345",
  "status": "ok",
  "ts": 1736723456000
}
```

**Обратная совместимость:** поддерживается legacy формат

## 📱 Пользовательский интерфейс

### **Навигация:**
- **Поворот энкодера:** навигация по меню
- **Короткий клик:** выбор/подтверждение
- **Длинный клик (700мс):** возврат/выход

### **Экраны:**
1. **HOME** - статус системы, WiFi, сервер, датчики
2. **RELAYS** - ручное управление реле и статус
3. **SENSORS** - показания SHT31 (температура/влажность)
4. **SOIL** - влажность почвы по 16 каналам
5. **SERVER** - тест подключения и настройки

### **Состояния сервера:**
- **OFF** - никакой серверной активности
- **ON** - полная интеграция: auth→telemetry→config→WebSocket
- **TEST** - комплексная проверка: auth→manifest→heartbeat с прокруткой результатов

### **TEST экран (полное соответствие серверу):**
- **Последовательность:**
  1. 🔐 AUTH TEST → POST /api/v1/device/auth
  2. 🌐 WEBSOCKET TEST → wss://vyroslo.replit.app/ws?token=JWT
  3. 💓 HEARTBEAT TEST → HEAD /api/
  4. 📊 TELEMETRY TEST → готовность POST /api/v1/device/telemetry
  5. ⚙️ CONFIG TEST → готовность GET /api/v1/device/config
  6. 📋 MANIFEST TEST → PUT /api/v1/device/manifest
- **Отображение:** Полноэкранная прокрутка (6 строк × 21 символ)
- **Навигация:** Построчная прокрутка энкодером без подсказок
- **Блокировка:** 3 секунды после показа результатов
- **Выход:** Долгий клик после разблокировки
- **Адаптивность:** Автоматический перенос длинных строк
- **Персистентность:** Состояние ON/OFF сохраняется в NVS

### **LED индикация (опциональная):**
- **Зеленый** - Online (WebSocket подключен)
- **Желтый** - Ожидание/Backoff
- **Красный** - Auth Blocked

## 🔬 Сенсорная подсистема

### **SHT31 датчики (I2C):**
- **0x44** → air_top (верхний датчик)
- **0x45** → air_bot (нижний датчик)
- **Параметры:** температура (-40...+125°C), влажность (0-100%)

### **Датчики почвы (мультиплексор):**
- **16 каналов** аналоговых датчиков
- **Стабилизация:** 14 измерений с отбрасыванием выбросов
- **Фильтрация:** детектирование floating сенсоров
- **Калибровка:** air_value=4095, water_value=1500
- **Сглаживание:** скользящее среднее по 3 секундам

### **Датчик уровня воды:**
- **Канал:** CH14 через мультиплексор
- **Тип:** аналоговый с порогом 1200
- **Логика:** water.low = (reading < 1200)

## 🔄 Рабочие циклы

### **Startup последовательность:**
1. Инициализация GPIO, I2C, дисплея, энкодера
2. Сканирование SHT31 датчиков (0x44, 0x45)
3. Подключение к WiFi (d3xr/d3xr-home)
4. NTP синхронизация времени
5. Запуск UI с главным экраном

### **Server цикл (точное соответствие ожиданиям сервера):**
1. **🔐 Аутентификация** (обязательно первый)
   - POST /api/v1/device/auth → JWT токен на 7 дней
2. **🌐 WebSocket подключение**
   - wss://vyroslo.replit.app/ws?token=JWT
3. **💓 Heartbeat** (каждые 5 сек)
   - HEAD /api/ → статус устройства: online
4. **📊 Телеметрия** (каждые 10 сек)
   - POST /api/v1/device/telemetry + JWT Authorization
5. **⚙️ Конфигурация** (каждые 60 сек)
   - GET /api/v1/device/config + JWT Authorization
6. **📋 Манифест** (при первом запуске после config)
   - PUT /api/v1/device/manifest + JWT Authorization

### **Sensor цикл (постоянно):**
1. **Ротация мультиплексора** (1 канал за цикл)
2. **Стабилизация измерений** (14 сэмплов с фильтрацией)
3. **Сглаживание значений** (экспоненциальное среднее)
4. **Обновление кольцевого буфера** (каждую секунду)

## ⚠️ Обработка ошибок

### **HTTP статус коды:**
- **200** - Успех
- **304** - Not Modified (ETag cache hit)
- **400** - Ошибка валидации (манифест)
- **401** - Неверные credentials ИЛИ истек JWT
- **404** - Устройство/манифест не найдено
- **429** - Rate limit (всегда с Retry-After)
- **5xx** - Серверная ошибка

### **401 семантика (важно!):**
- **401 на /auth** = блокировка до перезагрузки
- **401 на других endpoint'ах** = повторная аутентификация

### **Rate Limiting:**
- **Экспоненциальный backoff:** 30сек → 1мин → 2мин → ...15мин
- **Retry-After:** строгое соблюдение заголовка
- **Jitter:** случайная задержка ±30сек

## 📈 Производительность и ограничения

### **Сетевой трафик (типичный час):**
- Телеметрия: 360 запросов × ~1KB = ~360KB/час
- Heartbeat: 720 запросов × ~100 байт = ~70KB/час
- Конфиг: 60 запросов × ~500 байт = ~30KB/час
- **Итого:** ~460KB/час исходящего трафика

### **Ограничения платформы:**
- GPIO 35 input-only (реле не переключается физически)
- Один ADC канал через мультиплексор (поочередное чтение)
- WebSocket reconnect каждые 5 секунд при обрывах
- NTP зависимость для корректных timestamp'ов

### **Масштабируемость:**
- До 16 датчиков почвы (ограничение мультиплексора)
- До 2 SHT31 на I2C шине (0x44, 0x45)
- Легкое добавление новых реле (при наличии GPIO)
- Расширение UI экранов через enum UiState
