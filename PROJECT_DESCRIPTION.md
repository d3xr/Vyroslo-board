# Проект: Прошивка для ESP32 «Vyroslo-board» — умная теплица

## Назначение

Прошивка реализует тонкий клиент для ESP32, предназначенный для управления и мониторинга умной теплицы. Устройство синхронизируется с сервером Vyroslo, публикует свой манифест, отправляет телеметрию, получает конфиг, управляется по WebSocket и поддерживает резервное управление через REST-интерфейс.

---

## Основной функционал

1. **Авторизация**
   - POST /api/v1/device/auth с device_id и secret.
   - Получение и хранение JWT-токена в NVS.
   - Обработка ошибок (401 — блокировка, 429 — лимиты, 5xx — бэкофф).

2. **Публикация и синхронизация манифеста**
   - Генерация локального JSON-манифеста устройства (описание железа, сенсоров, реле, мультиплексора, дисплея, элементов управления).
   - GET /api/v1/device/manifest с If-None-Match: <etag>.
   - PUT /api/v1/device/manifest при изменении локальной конфигурации или 404 от сервера.
   - Хранение manifest_etag и времени публикации в NVS.

3. **Телеметрия**
   - POST /api/v1/device/telemetry каждые ~10 секунд.
   - Формат: device_id, ts, fw, hw, sensors (air, soil, water), relays, rssi_dbm, uptime_sec.
   - Rate limiting, обработка 429/Retry-After, бэкофф.

4. **Конфиг**
   - GET /api/v1/device/config с If-None-Match: <etag> каждые ~60 секунд.
   - Применение новых параметров (интервалы, расписания, пороги).
   - Хранение etag и последнего конфига в NVS.

5. **Heartbeat**
   - HEAD /api каждые 2–5 секунд (без JWT).
   - POST /api/v1/device/heartbeat (опционально, с лимитом).

6. **WebSocket**
   - wss://vyroslo.replit.app/ws?token=<JWT>
   - Управление реле: {"type":"relay_control", ...}
   - ACK на команды, таймауты авто-выключения реле.
   - config_update: триггер обновления конфига.
   - Реконнект каждые 5 секунд.

7. **Fallback-управление**
   - GET /api/v1/device/inbox при отсутствии WS.
   - Выполнение команд, отправка ACK через POST /ack или WS.

8. **LED-индикация**
   - Зеленый — online (WS подключен).
   - Желтый — ожидание/backoff.
   - Красный — authBlocked.

9. **Хранение в NVS**
   - JWT-токен, etag манифеста и конфига, время публикации манифеста, последний конфиг.

10. **Rate limiting и backoff**
    - Соблюдение лимитов для всех типов запросов.
    - Экспоненциальный бэкофф с jitter.
    - Обработка Retry-After.

## Структура проекта

- **src/main.cpp** — точка входа, основной цикл, инициализация.
- src/network.cpp / include/network.h — сетевые функции, авторизация, heartbeat, WebSocket.
- src/manifest.cpp / include/manifest.h — генерация и синхронизация манифеста.
- src/relays.cpp / include/relays.h — управление реле, таймауты, ACK.
- src/sensors.cpp / include/sensors.h — работа с датчиками (температура, влажность, почва, вода).
- src/led.cpp / include/led.h — управление LED-индикацией.
- src/storage.cpp / include/storage.h — работа с NVS (сохранение/загрузка токенов, etag, конфигов).
- src/config.cpp / include/config.h — обработка и применение конфига.
- src/ui.cpp / include/ui.h — отрисовка интерфейса на дисплее, обработка кнопок/энкодера.
- src/server.cpp / include/server.h — серверный цикл, обработка команд, fallback.
- src/ratelimit.cpp / include/ratelimit.h — реализация лимитов и бэкоффа.

## Логика работы

- При включении — инициализация, подключение к Wi-Fi, авторизация.
- Синхронизация манифеста с сервером (GET/PUT).
- Запуск WebSocket, планировщиков телеметрии, конфига, heartbeat.
- Обработка команд управления реле через WS или inbox.
- Применение новых конфигов и обновление манифеста при изменениях.
- LED-индикация состояния.
- Хранение всех ключевых данных в NVS.
- Соблюдение лимитов и обработка ошибок по протоколу.

## Проблемы и задачи

- После рефакторинга возможны ошибки компиляции из-за отсутствия или дублирования определений, неправильных includes, несовпадения типов.
- Требуется тщательная проверка всех заголовочных файлов, чтобы все переменные, константы и функции были доступны во всех нужных модулях.
- Необходимо обновить устаревшие вызовы ArduinoJson.
- Важно протестировать все сценарии по критериям приёмки из ТЗ.

Проект реализует современный контракт для ESP32 с сервером Vyroslo, поддерживает автогенерацию UI, резервное управление, хранение состояния, обработку ошибок и лимитов, а также удобную структуру для поддержки и расширения.
